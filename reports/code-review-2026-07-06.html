1 · Action needed: existing imported data

Rows already in the database were imported with two now-fixed bugs, and the dedup row-hash bakes both in:

  • Excel dates one day early — every date from SwissCard, CornerCard, and both accounting .xlsx exports.
  • camt.053 NOTPROVIDED references — previously stored as a real reference; now treated as absent (they made distinct same-day, same-amount rows hash identically, silently dropping the second one).

Because the fixes change the computed row hashes, re-importing previously imported files will duplicate rows instead of skipping them.

Recommendation: pnpm db:reset and re-import all statements. Matching decisions were made against shifted dates anyway, and a clean re-import also recovers any camt rows the old dedup silently dropped. Alternative if you want to keep confirmations: a one-off migration that shifts Excel-sourced dates +1 day and rehashes — say the word and I'll write it. Until decided, avoid re-importing old files.

5 · Visible behavior changes to be aware of

  • The reconcile queue's "open" filter now matches its badge. Previously the filter showed every card debit with open status — 1,376 rows in your data, 1,368 of them unclassified — while the badge said 8. Both now use one definition: classified to a company but not fully reconciled. Unclassified items live under the "Unclassified" filter as before.
  • Matching output will change (for the better) on the next run: grouped reimbursements are actually found now, stale FX rates refresh, dismissed pairs stay dismissed, and cross-currency candidates without a real rate disappear instead of showing fake perfect scores.
  • Confirming can now return a clear error ("already matched", "no FX rate") instead of silently creating a second group — the toast tells you to re-run matching, which refreshes candidates.
  • Imports skip errored rows and say so instead of committing zeros; camt.053 batch entries without per-transaction amounts import as one entry-level row with a warning.

7 · Larger improvements worth planning

  1. Candidate-cache invalidation model. The double-match guard now blocks wrong confirmations, but stale candidates still linger until a re-run. Finish the design the schema anticipates (stale, runId): any confirm/revoke/import marks candidates referencing consumed transactions.
  2. Dedup hash versioning. Twice in this review a parser fix changed row identities (§1). Store a hashVersion on batches/transactions so future normalization changes can rehash instead of double-importing.
  3. Preset-driven re-read. Restructure analyzeFile to detect → resolve preset → read-with-preset-options → map, making preset delimiter/encoding/sheet/header settings effective and rescuing mis-sniffed files.
  4. camt.053 golden fixtures. Anonymized real Raiffeisen exports as checked-in test fixtures (multi-TxDtls batches, FX legs, reversals, counterparty fields). Every camt bug found here stemmed from untested structural variants.
  5. URL-driven list state + wizard order. Move filter/sort/page/search into validateSearch params (back-button-safe, shareable) and let the review wizard walk the same filtered set the queue page showed. Also: detect end-of-queue and navigate home with an "all reviewed" toast instead of stranding the user.
  6. Push dashboard/queue aggregation into SQL. Both endpoints load entire ledgers (including rawPayload JSON) and aggregate in JS; the wizard refetches the full queue after every action. A few GROUP BY queries and a lightweight ordered-id endpoint keep the hottest paths O(result).
  7. Recon status as derived data. accountingLinked/bankLinked/reconStatus are denormalized flags maintained from six call sites — easy to miss one. Consider a view or a single recomputeAll() after structural changes.
  8. Tooling baseline. No linter, formatter, or CI. Suggest Biome (one fast tool, minimal config) + a GitHub Actions workflow running typecheck / test / build. Cheap insurance for code moving financial numbers.

8 · Test-coverage gaps

32 tests now cover the pure helpers plus regressions for the date/indicator fixes. Highest-risk untested surfaces, in priority order:

  • mapRowsToCanonical — remaining sign conventions (invertSign, two_columns, positive_is_debit), currency-in-cell splitting, drop rules. This is where sign-inversion bugs live.
  • Engine window construction and candidate lifecycle — extract the window/pool logic into pure functions and test them; the inverted group window would have been caught immediately. Include used-exclusion and dismissed filtering.
  • rates.ts — staleness bound, carry-forward, inversion, CHF-hub cross rates, mixed-decimal convertMinor, ensureChfRates with a mocked fetch.
  • Dedup hashing — occurrence semantics, duplicate references, re-import idempotency across overlapping files.
  • Parser fixtures — camt.053 (batch entries, FX legs, leading-zero refs, NOTPROVIDED), MT942, Raiffeisen continuation merging, BOM'd files through detectKind.
  • Boundary cases — scoreAmountPair at exactly tol/2·tol, findSubsetSums caps and no-solution, negative and 3-decimal amounts in money.ts.

9 · What the codebase does well

  • Money as integer minor units everywhere — amounts, CHF equivalents, matched amounts, tolerance math. No floating point in financial arithmetic; the single rounding point lives in money.ts.
  • UTC epoch math for calendar dates in date.ts — immune to the DST off-by-one class of bugs (the Excel issue was at the xlsx boundary, not here).
  • Idempotent import core: content-addressed file hash, per-row content hash with occurrence indexing that preserves legitimate same-day duplicates, all committed in one transaction with batch bookkeeping.
  • Bounded subset-sum: descending sort + overshoot pruning + pool/size caps make grouped-match search worst-case ~22k nodes — no exponential blowup.
  • Correct TanStack Start patterns: route loaders with ensureQueryData and shared query options, hierarchical query keys, invalidation instead of manual refetch, no useEffect data fetching anywhere.
  • The undo system — compensating server calls with server-returned prior state for bulk operations, useSyncExternalStore for the badge, native text-undo respected in inputs.
  • DTO discipline: rawPayload stripped from every client-bound row; note DB helpers split into a server-only module so they can't ride into the client bundle.
  • SQLite done right for a local app: WAL, foreign_keys = ON, busy_timeout; user decisions preserved across matching re-runs (dismissals kept — and now actually honored — groups soft-revoked).
